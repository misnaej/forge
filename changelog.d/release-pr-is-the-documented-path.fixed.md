- **Cutting a release now points at the command that actually does it.** One command assembles the notes, commits, pushes and opens the pull request. Nothing said so: the reminder printed after every sync named a different command — the one that prepares the work and then stops, leaving the commit, the push and the pull request to be done by hand. Anyone following that reminder took the long way round, met every check designed for hand-written code, and needed a bypass to publish. The reminder, the project guide and the release document now all name the command that finishes the job, and describe the other as what it is: the same work, stopped early, for when you want to look before committing.
- **A fix now has to land somewhere the next person will read.** A new rule states that a defect found during work is not fixed by describing it — it belongs in the tool's own output, the rules, the skill, the documentation or the code, whichever the next reader meets first. Filing a ticket records what is owed but leaves the next person to rediscover the problem. The test the rule sets is whether the change would have prevented the mistake with nobody remembering it.
