- **The emergency now lasts as long as the work it was called for.** Forge has a deliberate way through when something must ship and the usual verification cannot run: a person arms it, it announces itself on a public issue before it exists, and it expires on a timer. It stopped the moment the pull request opened — but that is not when the work ends. The conflicts, the review corrections and the follow-up commits all arrive afterwards, and each one met the full battery again on a branch whose emergency had not run out. Publishing stays a single use, exactly as before; what now lasts until the timer is the pause on the two checks that compare your local install against the project. Every safety guard remains untouched, and a check that has actually found something still stops the commit — an emergency defers verification, never a failure someone already has in hand.
- **The one agent allowed to commit no longer refuses during an emergency.** It confirms, before committing, that the recorded check results describe the exact tree it is about to commit — which is right, and caught three real mistakes today. But arming an emergency writes a file and so changes that tree, ageing the very evidence the check demands: the bypass could not reach the commit it was armed for. During a live emergency, aged evidence no longer stops the commit, and the agent says so when it hands back.
