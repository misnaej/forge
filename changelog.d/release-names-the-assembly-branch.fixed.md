bump: patch
- **Staging a changelog assembly by hand now tells you where to commit it.** Opening the assembly pull request is one command, and a second command exists to stage the same work for inspection and stop before committing. What the second one did not say is that the automatic path recognises an open assembly only by its branch name, so an assembly committed anywhere else is invisible to it and a duplicate gets opened alongside. It now names the branch to use, and explains that the entries it just consumed will make the automatic command report nothing pending until the assembly lands.
- That branch name is now built in one place and printed from it, so the name in the message and the name the automatic path creates cannot drift apart. The release documentation also no longer describes the staging command as a way to inspect an assembly without consequence, and attributes the duplicate guard to the command that actually has it.
