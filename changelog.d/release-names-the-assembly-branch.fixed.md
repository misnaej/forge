- **Staging a changelog assembly by hand now tells you where to commit it.** One command opens the assembly pull request outright; another only stages the same work, for when you want to commit it yourself. The second never mentioned that the first recognises an already-open assembly solely by its branch name — so an assembly committed on any other branch is invisible to it, and the scheduled weekly run opens a duplicate alongside. It now names the branch to use, and warns that the entries it just consumed will make the first command report nothing pending until the assembly lands.
- The release documentation no longer describes the staging command as a way to inspect an assembly without consequence, and credits the duplicate guard to the command that actually has it rather than the one it happened to sit beneath.
