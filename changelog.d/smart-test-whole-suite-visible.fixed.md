bump: patch
- `forge-smart-test` no longer runs test files that are not part of the suite. A test file git ignores — a scratch copy, anything under an ignored directory — or one pytest's own configuration excludes through `--ignore`, `--ignore-glob` or `norecursedirs` is now left out of the selection, read from whichever of `pytest.ini`, `pyproject.toml`, `tox.ini` or `setup.cfg` pytest itself would use. Forge has to apply those rules itself, because it hands pytest explicit file paths and pytest's ignore settings only govern the directories it walks. A file that is merely untracked still runs, so a new test works before it is added to git.
- Two deliberate asymmetries, both in the direction of running too much rather than too little: only files that would be collected as tests are filtered, so an ignored `conftest.py` keeps its place in the import graph and the tests depending on it stay reachable; and when git cannot answer the question at all, nothing is filtered, because a filter that failed closed would drop every test and report a passing run.
- Every tier now says how much of the suite it is about to run — `=== depth 0: 112 of 112 test file(s) ===` — and warns when that is nearly all of it, naming the cause where there is one to name: a changed `conftest.py`, a changed package `__init__.py`, or neither. Editing a shared conftest has always turned the cheapest tier into a full run; now it says so instead of looking like a hang. The escalation itself is unchanged: this makes it visible, it does not avoid it.
- Output arrives while the run is happening instead of in one block at the end, for tiered and whole-suite runs alike. The log keeps the same text and callers get back the same output, so nothing that reads a run's output changed.
