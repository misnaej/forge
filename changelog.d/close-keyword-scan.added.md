bump: minor

- **An issue a PR only partly delivers no longer gets closed by surprise.** GitHub closes an issue when a close keyword sits next to its number anywhere in a PR description — "closes #504's doctor half" closes all of #504 — and forge's summary only counted bare `Closes #N` lines, so such a closure went unseen. `forge-pr-create` now warns before publishing when the description would close an issue that summary does not list, and the wrap-up's Issue Management line adds "GitHub would also close (on merge into the default branch): #N". FOUNDATION §6 "PR descriptions" states the rule — a PR delivering part of an issue writes `Part of #N`, and only the completing PR closes it — `/plan-issue` makes a plan that splits an issue across PRs name the one that closes it, and `pr-manager` no longer claims GitHub ignores a keyword inside a sentence. New `pr_delta.find_loose_closing_refs` / `unlisted_closing_refs` scan a description for closing keywords anywhere in the text.
