bump: minor

- `forge-next-prep --prune-remote` deletes origin branches whose same-repo PR merged into the base branch and whose tip has not moved since. Each delete is pinned to the merged commit, so a branch that received a push after the merge is reported and left alone, as are branches with an open PR or no merged PR; the base branch and the branch `origin/HEAD` names are never touched. A branch whose PR state `gh` cannot report is skipped with a warning; if `gh` is missing, unauthenticated or times out, the run stops there and deletes nothing further, and if `git ls-remote` fails nothing is deleted. At most 50 branches are examined per run; the rest are reported unexamined. A deleted branch is restorable from its PR page. `/next` always passes the flag. The delete goes through a new `forge.git_utils.delete_remote_branch`, which refuses the base branch and malformed names or commits itself.
- The commit agent can no longer delete remote branches: a push that deletes (`--delete`, `-d`, `:branch`, `--mirror`, `--prune`, by any prefix git accepts), a push whose refspecs come from a variable, a command substitution or `xargs`, and a `gh api` DELETE of a branch are refused for it and point at `forge-next-prep --prune-remote`, or at running it yourself with `!`.
- When a command is refused for carrying AI attribution, the message now says the whole command was refused and nothing in it ran — including anything chained before it — so a retry re-runs all of it rather than only the commit.
- The commit agent stages in a separate call, checks that the staged files match the request before committing and that the commit holds exactly those files before pushing, and after a refused commit restarts from staging.
