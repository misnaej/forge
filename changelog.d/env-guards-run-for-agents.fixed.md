- **The two checks that catch a stale development environment have never run on an agent-driven commit, and now do.** Forge blocks committing directly so that every commit goes through an agent, and the checks that catch a broken setup — an install built from a different clone, git hooks left behind by an older version, a Claude Code plugin cache older than the plugin you are shipping — each stood down whenever no terminal was attached. An agent never has one, so on the standard commit path both checks skipped every single time, while the documentation said they blocked. On this project's own machine their logs read "skipped" going back as far as they were kept. They now stand down only in continuous integration, which is what was meant. **You may see a commit blocked that previously went through** — that is the check working; the message names the command that fixes it. The automatic environment rebuild is deliberately unchanged, because it acts on your machine rather than reporting, and an agent's commit is not the place to do that unasked.
