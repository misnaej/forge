bump: minor
- **Four checks had silently stopped working after agents were renamed, and three of them were guards.** When v14.0.0 renamed shipped agents, the places that *announce* a name were updated and the places that *match* on one were not — and a comparison against a name nothing is called any more does not fail, it just stops recognising anything. The pre-commit fixer's shell restriction stood aside for the real fixer, so it was not restricting; the hook that requires the fixer to reach a verdict was never invoked at all, because the wiring selected it by a pattern that matched nothing; the cap that notices the fixer running past its three-run limit could never fire; and per-agent token accounting folded every forge agent into its "something else" bucket, so recorded figures attributed nothing. All four work again.
- **The cause is fixed, not just the names.** Forge's hook wiring now names an agent by its permanent stem rather than by the name it is addressed under, and the installer resolves that to whatever the current name is — building the pattern, and telling the guard which agent it restricts. No guard script and no pattern spells an agent name any more, so renaming an agent cannot leave one behind. A stem naming no shipped agent now fails at install time rather than quietly matching nothing, and it is checked against the agents actually present on disk, because the alternative read returns an empty list when it fails and would have approved anything.
- **A guard that cannot tell which agent it restricts now says so on every call instead of standing aside.** Previously that condition was indistinguishable from "some other agent" and passed in silence, which is how the restriction went missing. It does not block: this guard runs on every shell command, and taking a session down over a configuration fault is worse than the narrow restriction being absent — but it is now absent *loudly*.
- Messages, help text and documentation that named agents and slash commands in their retired forms are corrected throughout, including the base-sync tool's advice to "spawn forge:merge-resolver", which a reader had to translate before it would work. The forge-only triage wrapper in this repo was delegating to a name that resolved only on a machine that still had the retired plugin installed.
