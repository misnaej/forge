bump: patch

`forge-doctor` now checks the forge plugin copy this repo actually uses, instead of whichever copy is newest on the machine — so a repo still running an older plugin is no longer reported as current because another repo fetched a newer one. When Claude Code has no install record for the repo, a new advisory says the verdict came from the newest cached copy, which may be another repo's. For consumer repos it compares the plugin's contents (agents, skills, hooks and manifest), so a rewritten agent or a hook fixed under the same name is caught, where before only missing hook names were. Two new advisories explain cases no update command can fix: a global (machine-wide) forge install beside this repo's own, with the uninstall command; and a machine-wide marketplace source that tracks a different ref than this repo pins, with how to re-point it. None of these change `forge-doctor`'s exit code, and `--skip-plugin-checks` now also suppresses the plugin-cache and global-install advisories. `install-forge-claude-settings` now points at `forge-doctor` after enabling the plugin, and the docs say plainly that the plugin is enabled per repo while its source is registered per machine.
