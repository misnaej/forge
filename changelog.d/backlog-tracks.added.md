bump: minor

- `forge-plan-check` gains three checks across a set: `tracks` lists open issues that name the same files as each other or as an open PR, the `track:*` labels already applied, and which files bind which issues; `current` reports, per issue, whether any merge touched its files since it was filed; `merge-order` probes open PRs against the base and each other without checking anything out, then suggests an order with "refresh after" notes (at most 20 PRs; more is reported).
- A posted wrap-up's Issue Management section now lists the issues its findings were deferred to or filed as (`deferred to #N`, `filed as #N`), so the issues a PR filed can be found mechanically.
- `/plan-batch` now runs the whole backlog-clearing method: it re-checks that each queued issue is still real in current code, groups issues into tracks that ship as one PR, puts every grouping decision to the user in one round, drafts and records one plan per track on every member issue, and gives the user a merge order for the resulting PRs. A queue nobody groups still batches issue by issue.
- `/sentinel` executes a track plan as one branch and one PR that closes every member issue (or is `Part of` one it delivers only partly), marking pickup and the opened PR on each member; still one track at a time.
- `/pr` places the issues a PR filed into tracks in the background once the wrap-up posts, through a new `placement` mode of `issue-triage`; it labels only when the fit is clear, asks the user when it is not, and never comments on the PR. The post-merge triage pass re-checks those placements.
- FOUNDATION §14 documents `track:<name>` as the grouping-label convention, and the agent template fixes the exact wording a wrap-up uses to name a follow-up issue (`deferred to #N`, `filed as #N`).
