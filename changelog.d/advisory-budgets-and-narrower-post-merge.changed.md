bump: minor
- **A word budget no longer refuses anything you have written.** Commit messages, squash-merge messages and PR wrap-ups each name a target the prompt asks for; a message past it warns once and still goes out. Refusing at a word count sent the author back to re-cut text that was already written and already correct, which costs more than the words it saves. The margin before that single warning is also wider than it was.
- **What makes a message quick to read turned out to be what it leaves out, not how long it is.** Across the last sixty merged squash messages, a quarter carried at least one bullet that told the reader nothing — that tests passed, that pre-commit was green, that a changelog fragment existed, how many words one of forge's own documents now has, how many tests or suppressions were touched. Those accounted for about a tenth of all the words spent on bullets. Continuous integration already proves the first, the fragment is already enforced, and the rest is bookkeeping that means nothing in a project's permanent history. So the rule is now about content: a bullet states a change in behaviour or what it means for the reader, and never reports process state or internal counts. That rule, not a lower number, is what shortens a message.
- **The post-merge triage pass now touches only what the merge changed** — the issues the pull request closed, the validated plans its diff outdated, and its own follow-ups. It no longer looks for the next thing to work on, which charged every single merge for a pass over the whole backlog nobody had asked for; picking work is a separate, deliberate act.
- **The backlog index now refreshes itself about once a day, for free.** It used to be rebuilt on every merge, which is far more often than a backlog changes shape. Rather than move that to a timed job, the index is rebuilt by the first merge that happens after it has gone a day stale, and every other merge skips it. The staleness check reads the index's own last-updated time, which the data already being fetched carries, so a merge that skips pays nothing and a quiet week costs nothing at all. `forge-backlog-index --if-stale-hours <H>` makes this available to anything else that runs often, and the decision belongs to the command rather than to whoever calls it.
- **The next stage of a plan is offered, never started.** When work was laid out as several stages and one of them merges, the routine that picks up next work now names the following stage and waits. A plan stated once is not standing permission for each of its parts: between stages the plan may have been reordered, narrowed or dropped, and only the person who made it knows.
- **A fault inside the continuous-integration shortcut is now visible.** A check that can tell when a tree has already been tested is allowed to fail safely — when it cannot decide, the full suite simply runs. That safety was also its blind spot: a permanently broken check would have gone on quietly paying for a redundant full run on every build. It now raises a warning on the run itself, naming the fault, while still never failing the build.
