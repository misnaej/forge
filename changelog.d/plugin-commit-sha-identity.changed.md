bump: major

- **The Claude Code plugin is now identified by its commit, not a version number.** Forge's `.claude-plugin/plugin.json` no longer declares a `version`, so Claude Code keys the plugin on the commit your marketplace pin resolves to, and `/plugin update` now installs every release — including those cut between changelog assemblies. Before this, a tag could ship an older manifest version, and `/plugin update` answered "already at the latest version" while installing nothing (#529). `/plugin` now lists a commit instead of a version number; the release number lives in the tag and in the pip version.
- The shipped tooling understands a manifest without a version: `verify-forge-plugin-version` skips it, `forge-changelog release` leaves it untouched, `forge-next-prep --tag` reports that no tag is needed, and the assembly PR no longer claims a manifest sync.
- `forge-doctor` and the `plugin_sync` step judge the installed plugin by commit. Forge's own repo is checked against `origin/main`'s agents, skills and hooks, so `plugin_sync` now fires after every merge that touches them. A consumer is checked against the commit its pin serves, and is told when this machine's single `forge` marketplace registration serves another repo's pin, which no update can fix (#561).
- To pick up this release in Claude Code: `/plugin marketplace update forge`, `/plugin update forge@forge`, then `/reload-plugins`.
