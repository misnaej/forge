bump: patch
- **The agent report no longer attributes one session's work to every agent in it.** `forge-agent-profile` reads a transcript to say how many turns an agent took and whether it repeated itself. The record it reads that from names the *parent session's* transcript, not the agent's own — so every agent in a session was credited with the whole session's turns, tool calls and repeated commands. The visible result was a report where agents that ran for seconds claimed hours of activity, and where the same command appeared as a "loop suspect" under nineteen different agents, none of which had issued it. On this repo's own records the fix takes fabricated loop suspects from nineteen to zero and brings every run's active time back below its wall time. A transcript is now used only when its filename carries that agent's own identifier; otherwise the agent's real transcript is located from the session it ran in. Where no transcript survives — they are purged after a month — the report now says nothing about that run rather than inventing figures for it, and a run left that way can still be filled in from a scanned transcript directory, which it previously could not.
- **Deleting a file next to the continuation notes no longer depends on what else is on the line.** The guard that protects `.plan/CONTINUATION.md` decided what a command was deleting by scanning the whole command line, so a delete of an ordinary sibling file was refused whenever anything else on that line happened to mention the directory — a listing alongside the delete was enough. Which part of the line is now consulted depends on what is being protected. Naming the notes file anywhere in a command that also deletes is still refused outright, because that file cannot be recovered and a needless refusal costs only a retry; that half is unchanged, pipelines included. Only the *directory* shape is judged against the delete's own part of the line, which is what makes the sibling delete work again. Two refusals are therefore broader than strictly necessary and deliberately kept: a command that deletes something unrelated while merely mentioning the notes file elsewhere — in a comment, or in text after `&&` — is still refused. Telling that apart from a genuine deletion needs full shell parsing, and the guard errs toward refusing. Quoted text containing a protected deletion on a line of its own, such as an issue body quoting an example, is refused for the same reason; passing that text through a file avoids it.
