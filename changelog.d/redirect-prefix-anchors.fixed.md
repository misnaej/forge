bump: patch

- **A redirection placed in front of a command no longer hides it from the guards.** The shell accepts a redirection before the command name, so `2>&1 git push -f` is a real force push, yet the guards did not recognise it — nor `&>log gh pr merge 1`, `2>&1 pip install x`, `2>&1 git clean -fd`, `2>&1 rm -rf .plan/` or a redirection between a tool and its subcommand (`git 2>&1 push -f`, `gh 2>&1 pr merge 1`, `ruff 2>&1 check .`). Every guard now reads past such redirections. One harmless command is now refused as a side effect: `x &>log git push`, where `git` is only an argument — run it yourself with `!` if you need it.
