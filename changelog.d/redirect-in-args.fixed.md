bump: patch

- **A redirection among a command's arguments no longer hides it from the guards.** Each guard read a command's arguments only up to the next `&` or `|`, and the `&` of `2>&1`, `&>file` or `>&2` (or the `|` of `>|file`) counted, so `git push 2>&1 --force`, `git checkout 2>&1 -f`, `git restore 2>&1 .`, `git commit 2>&1 -n`, a protected-branch push such as `git push 2>&1 origin main`, `gh api >|x …/pulls/N/merge` and `git push origin >|x --delete main` all ran. The install guard and the inline-interpreter guard went further and stopped at any redirection after the command word, so `pip >/dev/null install x`, `uv run 2>&1 pip install x`, `uvx 2>&1 ruff check .` and `python <in -c '…git commit…'` passed too. The guards now read past redirections wherever they read arguments, including a target written as a command substitution (`>$(mktemp)`). Three commands that were refused only because of the same flaw now run: `git stash 2>&1 list`, `git revert HEAD 2>&1 --no-commit`, and a `--help` placed after a redirection.
