bump: patch

Pre-commit no longer passes silently over files you have not `git add`-ed. A check that reads its files from git never saw a new, untracked module, so a run could report PASS and the commit then fail on that same file. Now the affected step logs, the closing summary, `forge-precommit --verdict` (a `NOTE` line above the unchanged closing line) and the changed-files audit logs name every relevant untracked file as not checked, for you to add (forgotten work) or leave out (junk); gitignored files are never listed and nothing new blocks. In changelog-fragments mode a fragment must now be staged or committed to satisfy the changelog check: one that only exists in the working tree is named instead of counted. The precommit-fixer, git-commit-push and `/commit` guidance decides per file and never blanket-adds.
