bump: patch

- **Naming a tool by its full path no longer hides it from the guards.** `/usr/bin/git push -f`, `./git push -f` and `/usr/bin/env git push -f` run the same force push as `git push -f`, and `/usr/bin/gh pr merge 9` the same merge, yet the guards recognised only the bare names. Every guard now reads past a directory path in front of a tool or a wrapper such as `env` — including `/usr/bin/env ruff check .` and an inline interpreter started through `/usr/bin/env`. A quoted or backslash-escaped tool name (`'/usr/bin/git' push`, `\git push`) is not yet recognised. A different name that merely contains the tool's name (`forge-git-x`, `my-gh`) is still allowed, and so is a path that is only a redirection target (`>/tmp/git push -f`). The `git clean` guard also now reads its flags only after the `clean` command itself, so `X=clean-n git clean -fd` is no longer mistaken for a dry run. Two harmless shapes are now refused as a side effect: an assignment whose value ends in `/git` followed by a guarded git command (`FOO=a/git push -f`), and a local script named `git` or `gh`, which is treated as the real tool — run either yourself with `!` if you need it.
