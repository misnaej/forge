bump: patch
- **Pushes can no longer hang forever waiting for a password nobody will type.** Three places where forge pushes for you — the resync branch, the changelog assembly branch, and the tag that assembly cuts — ran the push with no time limit and no way to refuse a credential prompt. On a remote that stalls, or one that wants a password in a place where nothing can answer, the command waited indefinitely and took the session with it. All three now go through one shared push that gives up after two minutes and never prompts, and each reports the failure plainly instead of leaving you to guess. The tag push matters most: it runs unattended in CI, where nothing can answer a prompt. Two further tag pushes elsewhere in the release path are still unbounded and are tracked separately — fixing them changes how release tagging handles failure, which is its own change rather than part of this one. One of them also described its own failure wrongly, claiming an error would be raised when it would not; that is corrected.
- **A branch named with a leading `+` or `-` can no longer force-push over another branch.** Git reads a leading `+` on a refspec as "force", so a branch whose name began with one could push over a different branch entirely — including the protected one. Pushes now name the source and destination in full and refuse a branch or remote whose name starts with either character.
- **A stray environment variable can no longer switch off the pre-commit checks.** Git can be pointed at a different hooks directory, index, or even a different repository by environment variables alone. Anything inheriting such a variable would have committed with the checks silently skipped. Those overrides are now dropped for the duration of a commit and restored afterwards, and a push runs with them filtered out of its environment, so the repository's own configuration applies in both cases. Note the limits: this removes per-process overrides, not configuration. A hooks path changed with `git config`, or a repository that never had a local one, is not covered.
- **A breaking change can be marked in the squash message.** Conventional commits mark one with an exclamation mark before the colon, and forge's own versioning turns on whether a change is breaking — but the squash-message tool rejected the marker while the commit hook accepted it. So a breaking change could be marked on the branch and not in the permanent commit on the main branch, which is the one anyone reads later. The marker is now accepted, and the error message shows it.
- **A gate message no longer assumes who is asking.** The changelog gate told the reader that "a commit agent" meets it and stops; anything that commits on your behalf reaches that gate, so it now says so. Wording only — the gate itself is unchanged.
