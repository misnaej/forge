bump: minor
- **Pushes can no longer hang forever waiting for a password nobody will type.** Two places where forge pushes for you — the resync branch and the changelog assembly branch — ran the push with no time limit and no way to refuse a credential prompt. On a remote that stalls, or one that wants a password in a place where nothing can answer, the command waited indefinitely and took the session with it. Both now go through one shared push that gives up after two minutes and never prompts, and both report the failure plainly instead of leaving you to guess. One of them also described its own failure wrongly, claiming an error would be raised when it would not; that is corrected.
- **A branch named with a leading `+` or `-` can no longer force-push over another branch.** Git reads a leading `+` on a refspec as "force", so a branch whose name began with one could push over a different branch entirely — including the protected one. Pushes now name the source and destination in full and refuse a branch or remote whose name starts with either character.
- **A stray environment variable can no longer switch off the pre-commit checks.** Git can be pointed at a different hooks directory, index, or even a different repository by environment variables alone. Anything inheriting such a variable would have committed with the checks silently skipped. Those overrides are now dropped for the duration of the commit — and of any push forge makes for you — then restored, so the repository's own configuration applies. Note the limits: this removes per-process overrides, not configuration. A hooks path changed with `git config`, or a repository that never had a local one, is not covered.
- **A breaking change can be marked in the squash message.** Conventional commits mark one with an exclamation mark before the colon, and forge's own versioning turns on whether a change is breaking — but the squash-message tool rejected the marker while the commit hook accepted it. So a breaking change could be marked on the branch and not in the permanent commit on the main branch, which is the one anyone reads later. The marker is now accepted, and the error message shows it.
