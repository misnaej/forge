bump: patch

- **Guards now look at what the shell would actually run.** Text that only *mentions* a guarded command — a commit message, a PR or issue body, a heredoc, a search pattern — no longer gets refused as if it ran, so ordinary read-only work and writing about forge's own guards stop being interrupted. In the other direction, a guarded command wrapped in `bash -c "…"`, `sh -c`, `zsh -c`, `dash -c`, `eval`, `ssh <host> "…"` or a heredoc fed to a shell, or placed inside `"$(…)"` or backticks, is now checked exactly as if it were typed directly; before, it slipped past every guard. Asking a guarded tool for help (`--help`, `-h`) is allowed. Flags, refspecs and branch names are still read even when quoted, so a quoted `"--no-verify"` or `"HEAD:main"` stays blocked. Remaining known gaps: `${IFS}` tricks, variable indirection, `xargs`, a script piped into a shell, and wrappers nested more than one level deep with escaped inner quotes.
