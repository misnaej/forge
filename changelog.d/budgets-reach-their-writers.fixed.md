- **The wrap-up comment's length budget now reaches the writer before the text is written, instead of arriving as a complaint about text already finished.** The budget was previously enforced by refusing an over-long wrap-up; when that refusal became a warning, nothing was left to carry the number — it appeared in no instruction, no template and no command output, only in a message that fired after the fact and suggested shortening the *next* one. Wrap-ups roughly tripled. Each slot in the file now states its own allowance, the command that creates the file prints the total, and the warning says what to cut from the text in front of you. The number itself still lives in exactly one place and every mention is rendered from it, so there is nothing to keep in sync.
- The same "shorten the next one" wording is gone from the commit-message warning, which had the same problem: advice you cannot act on without writing a second commit.
- Nothing newly refuses. Over-length still posts and still commits, by design — the fix is telling the writer the budget early, not reinstating a gate.
