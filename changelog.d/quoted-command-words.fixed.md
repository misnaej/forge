bump: patch

- **Quoting a command's name no longer hides it from the guards.** The shell removes quotes before it runs a word, so `'git' push -f`, `g'it' push -f`, `git 'push' -f`, `gh 'pr' merge 9` and `'ruff' check .` run exactly what their unquoted forms run, yet the guards treated every quoted span as inert text and let them through. A quoted word that spells one plain word is now read as that word wherever it appears — as the tool, its subcommand, a wrapper such as `sudo` or `bash -c`, or inside a wrapped payload — including `'/usr/bin/git' push -f`. Quoted text that stays text is still ignored: a commit message, a PR body, `echo 'git' push -f`, and `gh 'pr merge' 9` (one argument, which gh rejects). A quoted `-h` / `--help` still does not count as asking for help. The install guard's shortcut that let any command mentioning `pip show`, `pip list`, `conda list` or a similar read-only command through is gone — it also let `pip show x && pip install y` slip past; read-only commands are still allowed, they are simply judged like everything else. Still not recognised: a name spelled with escapes inside `$'…'` (`$'\x67it' push`) and a quoted command word built from a variable or holding a blank. Two harmless shapes are now refused as a side effect: a quoted `NAME=value` word in front of a guarded command reads as an assignment, and a commit message that is a single flag-like word (`-m "--no-verify"`) reads as that flag — run either yourself with `!` if you need it.
