bump: patch
- **A managed-block marker is no longer mistaken for an agent reference and rewritten.** Shipped instructions name each other in a neutral form that each harness rewrites into its own namespace at install time. A managed block — the kind a tool writes between two comment markers so it can find and refresh its own output later — is spelled the same way, and when its first segment happened to match the name of a shipped skill, the rewriter treated the marker as a reference and renamed it. The architecture-diagram feature was affected: the installed instructions told you to write a marker its own generator then refused, so the feature could not be adopted by following them. Nothing silently misbehaved — the generator fails loudly — but the instructions and the tool disagreed, and the instructions were wrong.
- **The distinction is now structural rather than a list of names to avoid.** A reference ends at the name; a marker carries a further segment after it. That single difference tells them apart, so a marker is safe whatever it is called. The hazard was already known for the handoff note's own markers and had been held off by refusing to ever ship a skill or agent with the colliding name — a prohibition that had to be remembered separately for each marker, and was not remembered for this one. That reservation is gone, and the three other marker families that were relying on luck are now safe by construction.
- Nothing else about installing changes: a genuine reference is still rewritten exactly as before, and a name forge does not ship is still left alone.
