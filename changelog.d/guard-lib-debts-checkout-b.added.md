bump: minor

- `block_git_destructive` now refuses `git checkout -B <name> [<start>]` and `git switch -C <name> [<start>]` when `<name>` is an existing branch with commits `<start>` does not contain — the reset would drop them off the branch. A new branch name, or a move that only fast-forwards the branch, is still allowed. When the hook cannot check (a `cd` before it, a variable, a start point that is missing or ambiguous), it refuses; this includes `cd x && git checkout -B feat main`, which was allowed before.
- `check_commit_format` reads single-quoted messages (`-m '…'`) on macOS too. It no longer relies on GNU-only `grep -P`, whose absence made a correctly paired `FORGE_WIP_SYNC=1 git commit -m 'wip-sync: …'` blocked and an unpaired `git commit -m 'wip-sync: …'` allowed. It reads the first `-m` (the subject), and refuses the commit if the message cannot be read at all.
- The guard hooks share more of their library: the help-aware invocation check and the command splitter live in one place (each hook still names its own separators), the unused segment anchor is gone, and a hook whose copy of the library lacks a helper it needs now refuses the command instead of letting it through.
