bump: minor

- **The memory audit is now offered at the right moments, and true lessons stop being thrown away.** A new `forge-memory-audit` command counts the agent's memories added since the last audit; `/next` offers `/memory-audit` once that count reaches `[tool.forge.memory_audit].threshold` (default 5), and `/pr` offers it whenever a PR edits the rule files (`forge-pr-plan` now reports `rule_surface`). The audit gains two verdicts: **SHOULD-SHIP** — a true, shareable lesson — goes to the repo's lessons file (`docs/lessons.md` by default, never auto-loaded) or, for forge itself, to a forge report; **UNOWNED** — true but nothing in the repo can own it — is kept and labelled. A contradiction between a memory and a rule is now put to the user instead of always deleting the memory. A lesson is promoted into `CLAUDE.md`, a skill or an agent only when it comes up a second time, and a memory is deleted only after its new home has been written (FOUNDATION §12).
