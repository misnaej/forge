bump: minor
- Stacked PRs get first-class support in the commit gate, freshness check and monitor. `forge-commit --base origin/<parent-branch>` gives a stacked branch's first commit (before its PR exists) a sanctioned base for the one-fragment gate, and the gate's refusal now names that remedy; the PASS log prints the resolved base and fragment count. Wrap-ups record `verified-base:` next to `verified-at:`, and `forge-pr-plan --freshness` reports a base retarget (stacked child moved onto the merged parent's base) as `fresh: false` naming old and new base. The PR monitor no longer alerts on `CONFLICTING` for a PR whose base is another open PR's branch, and marks a stack child's CI failures as run against the unmerged parent. New `forge-pr-watch stack` lists the open stack in dependency order with each PR's base, mergeability, freshness and monitor state.
