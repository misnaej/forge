bump: minor

- **Saved check results can no longer mislead agents.** Forge's agents trust the result files in `code_health/` instead of re-running checks, so those files now say truthfully what they cover. Every forge tool finds the directory through one place, which the new `FORGE_CODE_HEALTH_DIR` environment variable can relocate — forge's own test suite points it at a temp directory per test and fails the run if anything still touches the real files, so a test can no longer leave a fake "passing" result behind. FOUNDATION §13 now states that a missing, empty, unstamped or incomplete result file means *unknown*, never *passed*, and the CI recipe shows a guarded way to gate on one. `forge-smart-test` stamps its log with the code it is about to test (not the code at the end of a long run), writes each depth tier as soon as it finishes, ends the log with a `# complete:` line, and refuses to start while another run is writing — naming that run — instead of overwriting its log. Audit logs record whether they covered the whole tree or only changed files (`# scope:`). The test-writer and test-advisor agents now judge a new test's cost from the timings its run already printed.
