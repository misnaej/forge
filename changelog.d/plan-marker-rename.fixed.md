bump: patch
- **A validated plan could stop being found, stalling autonomous execution in silence.** The comment prefix that carries a plan was spelled two ways: forge's reader and the shipped triage agent used `[issue-triage] plan-validated:`, while the foundation rules documented `[forge-issue-triage] plan-validated:` — the prefixed form agents gained in v14.0.0. An agent following the rules posted the prefixed spelling; the reader looked for the unprefixed one and did not match it, because the prefix sits between the bracket and the name rather than after it. The issue kept its `plan-ready` label, still inviting execution, while the plan behind it had become invisible. Both spellings were already in use on live issues, so this was reachable rather than theoretical.
- **The marker is now the prefixed form everywhere it is written** — reader, the triage agent, the planning, PR and sentinel skills, and the documentation — so one spelling is produced from here on.
- **The old spelling is still read, deliberately and temporarily.** Plans posted under it are sitting on open issues; refusing them would orphan work a human already validated. Both forms are accepted for a transition, and the unprefixed one is never written. It will be retired once no open issue carries one; the check is recorded as a search rather than a date, and tracked as its own task so it does not rest on anyone remembering. **No action required** if you use forge's own tooling: existing plans keep working, and anything posted from now on uses the new spelling. **If you have your own tooling that reads this marker**, teach it to accept both spellings — plans written from now on carry only the prefixed one.
