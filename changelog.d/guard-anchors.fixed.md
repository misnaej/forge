bump: patch
- **Five git/gh guards no longer miss a command that does not start the line.** `block_protected_branches`, `block_no_verify`, `block_claude_attribution`, `block_pr_merge` and `block_unverified_pr_create` matched their own hand-rolled `^git …` / `^gh …` patterns, so a leading space, an environment-variable prefix, a `cd … &&` chain or a subshell walked past all five. They now source the shared anchor library the rest of the guard family already uses (`GIT_ANCHOR`, and a new `GH_ANCHOR` for the `gh` guards), and fail closed if that library is unreadable. This matters most for `forge:git-commit-push`, the one agent exempt from `block_raw_git`: for it, these five were the whole protection.
- **`block_no_verify` catches the short form.** `git commit -n` is `--no-verify` and now blocks; `git push -n` is `--dry-run` and deliberately does not.
